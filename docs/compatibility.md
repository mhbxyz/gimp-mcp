## macOS: what differs

* The bridge is the same local Unix socket, in `~/Library/Application Support/gimp-mcp/` (folder
  `0700`); the peer's uid comes from `LOCAL_PEERCRED`.
* Skipped there: the Flatpak test (Linux only). Everything else in `tests/e2e` runs.
* Known limits of gimp.org's GIMP 3.2.6 macOS build (recorded in `docs/gimp-notes.md`): no
  `gegl:gluas` (no Lua), and lossless AVIF export fails in its AOM encoder (lossy AVIF works).
* x86_64 Macs (`gimp-3.2.6-x86_64.dmg`) are not verified: GitHub no longer offers Intel macOS runners.

## Windows: what differs

* The bridge is a named pipe, `\\.\pipe\gimp-mcp-<user>`: its DACL grants the current user only, remote
  clients are rejected, and the plug-in refuses a client whose process belongs to another user (the
  server checks the pipe's owner the same way). The token lives in `%LOCALAPPDATA%\gimp-mcp\`.
* Skipped there: the Flatpak test (Linux only). Unit tests of Unix-socket specifics are skipped and
  replaced by `tests/unit/test_windows_pipe.py`.
* NTFS ignores case but not the Unicode normalization form; file tools compare names accordingly
  (`docs/security.md#file-paths`). GIMP for Windows starts its own D-Bus bus (`gdbus.exe`), on
  loopback only.

## Not supported (not verified)

* **Windows 10/11 desktops** and Windows on ARM — not verified directly (CI uses Windows Server 2025, x86_64).
* **Intel Macs** and macOS versions other than 15 — not verified (GitHub offers no Intel macOS runner).
* GIMP installed from the Microsoft Store, Homebrew, MacPorts or MSYS2 — not verified; point
  `GIMP_MCP_GIMP_CONSOLE` at its `gimp-console-3.2` if it is not found.
* **Snap GIMP** — different confinement; untested. (Flatpak is supported, see above.)
* **GIMP 2.10 / 3.0** — refused at connection time.
* Remote GIMP over a network — by design the bridge is local only.

## Local permissions

Everything runs as the user, without privileges:

* the plug-in is copied to the GIMP 3.2 profile's `plug-ins/gimp-mcp-bridge/`
  (`~/.config/GIMP/3.2`, `~/Library/Application Support/GIMP/3.2`, `%APPDATA%\GIMP\3.2`, or
  `$GIMP3_DIRECTORY`);
* the socket and its token live in `$XDG_RUNTIME_DIR/gimp-mcp/` on Linux and
  `~/Library/Application Support/gimp-mcp/` on macOS (`0700`, socket and token `0600`); on
  Windows the pipe admits only the user and the token is in `%LOCALAPPDATA%\gimp-mcp\`;
* file tools read/write only the absolute paths they are given, with the user's
  permissions, and never overwrite without `overwrite: true`.

## Versioning and compatibility promise

[Semantic versioning](https://semver.org/). While the version is `0.y.z`,
minor versions may break compatibility; every change is listed in
`CHANGELOG.md`.

* **Public API**: MCP tool names, input schemas, output schemas and error
  `code`s, the CLI commands and their options.

  Its snapshot is [`docs/api/contract.json`](api/contract.json): every tool (name, toolset, input
  and output schemas, annotations), error code, prompt, resource and CLI option. Descriptions are left
  out: rewording is not a change. `uv run scripts/api_contract.py write` regenerates it, and the unit
  tests fail when it is out of date. On every pull request CI classifies each difference with the base
  branch (`scripts/api_contract.py check`):

  | Compatible | Breaking |
  |---|---|
  | new tool, prompt, resource, error code, CLI command or option | removed or renamed tool, parameter, output field, error code, prompt, resource, CLI command or option |
  | new optional parameter, parameter made optional | new required parameter, parameter made required |
  | wider type or range, new enum value | narrower type or range, removed enum value, changed default |
  | new output field | output field that may now be missing, or may now be null |
  | | tool moved to another toolset, read-only tool that now changes images |

  A breaking change fails the check unless `CHANGELOG.md` has a `### Breaking` entry under
  `## [Unreleased]`, and, from 1.0 on, unless the major version changes.
* **Internal**: the bridge protocol (versioned: `protocol: 1`) and the Python
  modules.

### Plug-in / server versions

The version is defined once, in `pyproject.toml`; the package, `gimp-mcp
--version`, the built artifacts and the installed plug-in (a `VERSION` file
written by `gimp-mcp install-plugin`) all derive from it. The plug-in reports
its version in the bridge handshake and the server applies this rule:

| Plug-in vs server | Verdict | Effect |
|---|---|---|
| identical | match | — |
| same MAJOR.MINOR, different PATCH | compatible | works; a warning is logged |
| different MAJOR or MINOR, or unknown | incompatible | every tool fails with `PLUGIN_VERSION_MISMATCH` (hint: `gimp-mcp install-plugin`, then restart GIMP) |

`gimp_status` and `gimp-mcp doctor` show both versions and the verdict.
* **GIMP-dependent**: procedure availability and names (`gimp_call_procedure`,
  `gimp_search_procedures`), fonts and rendering details. The coverage matrix
  (`docs/coverage.md`) is regenerated for each supported GIMP version.
