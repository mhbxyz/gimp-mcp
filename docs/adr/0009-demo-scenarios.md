# ADR 0009: Demo scenarios

Status: accepted (2026-11-08, #107)

## Context

v0.6.0 adds eight demos of typical GIMP work (#108–#115). Each must be reproducible, checked by
facts, runnable on every supported OS, shown as a video of a real agent, and free of unlicensed
material. One hard-coded script (`demo/thumbnail.py`) did this for one demo only.

## Decision

* A demo is a **scenario**: `demo/scenarios/<name>.py` defines `SCENARIO = Scenario(...)`
  (`demo/harness.py`) with its toolsets, assets, outputs, scripted steps with checks, and the
  prompt and expected export of its agent version.
* The **scripted** version runs with the toolsets it declares and nothing else, so it proves they
  are enough; its checks are facts (sizes, trees, text, pixels, files read with Pillow), recorded
  with every tool call in `report.md`.
* The **agent** version is the scenario's prompt, on files in `~/inputs` (its assets and generated
  inputs), given to Claude Code in the isolated video
  container (`demo/video/record.sh VERSION SCENARIO`); its result is not asserted by CI (the agent
  evaluation suite, #106, measures agents).
* `tests/e2e/test_demo_scenarios.py` runs every scenario on a real GIMP in the e2e jobs (Linux,
  macOS, Windows) and verifies its files again, independently of the scenario's own checks; a
  scenario without such independent verifications fails that test.
* Every asset has a source and a license in `demo/assets/LICENSES.md`; a scenario using an
  unlisted asset is refused. Assets are generated by code in the repository or carry a free
  license that allows redistribution.

## Consequences

Adding a demo is one module, one row in `demo/README.md`, its assets with their licenses, and its
independent verifications in the e2e test. The e2e suite grows by the runtime of every scenario.
